# Data-buffer measurement method

Baseline: uploaded bdae610c073a215d1fe85727ef85a2a8062ea238. New benchmark inherits compact's independent full-sort truth, exact cross-mode digest and complete reopened key/value check. All modes explicitly use format03,1MiB index cache and slicing8 CRC. Variable pair is data-cache bytes:scan-local-cache bytes. Default experiment arms:0:1MiB (current production),1MiB:0,4MiB:0,16MiB:0,16MiB:1MiB. Each sample writes a fresh database; no old dataset modification.

Fixed runtime image sha256:f13894c3a9c42d574a5c31b2ab61e95dc4a0c383f95572cf9d2b79238c0da620 loads the newly built benchmark by read-only bind mount. No network, read-only root,2CPU/512MiB. Native Linux data under/var/lib/minivectordb-compact resides in the D-backed MiniVectorDB WSL disk. All harness/build/output/temp files are D. Runs serialized; no concurrent tests or compilation during timed experiments.

Three alternating/rotating rounds per performance group. Main query time excludes two warm-up queries and independent full-sort truth. First query is separately timed with a result sink and independently checked. It runs after writing (and after update/delete in churn); OS cache can be warm and churn can already populate the application cache. Thus this is first-query-after-DML latency, not a cold-disk guarantee. Constructor/table setup and the first cache-array allocation may precede this timer; do not claim complete startup latency. Main query comparison has identical output collection and workload in all arms.

Counter resets retain cache contents. Data-cache statistics are separate from unchanged index-cache statistics. Budget includes the allocated data entry/set array, while fixed Store objects, allocator metadata, scan-local cache, current row, query/driver inputs and independent truth are extra. RSS/cgroup peak includes all of them and is not engine-only memory. Caches close with Store; reopening starts empty and fully validates disk data. Full SQL row validation executes even when data pages hit.

Standard2000rows/40queries then10000rows/200queries. Variations:ordered insertion,5000-byte text,16-dimensional/no text,768-dimensional vectors,1% filter,update/delete churn. At30000rows standard layout live packed payload alone exceeds16MiB, testing eviction beyond capacity. Compare both main query time and first-query latency, hits/misses/evictions, writes, identical file sizes and observed memory. Preserve unfavorable results; default selection favors representative benefit with a bounded ceiling, not universal optimality.

Source and binary SHA256 captured before and verified after each run. JSONL flushed after each sample. Main exact query checks, first-query checks and full reopened maps reported separately. Diagnostic runs enable timers and are excluded from speed claims. Earlier results remain untouched. No physical-SSD IO, official workload, rank or score claim follows.
