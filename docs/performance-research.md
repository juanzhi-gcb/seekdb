# MiniVectorDB 文献结论与 A/B 实验建议

日期：2026-11-09。状态：下文记录首次文献调研时的方案与假设；随后执行的局部实验见 validation.md 和 bench/README.md。Agent 调研不构成学生自身学习成果或正式提分证据。

## 适用边界

本题为自研、单机单客户端 SQL 数据库，默认 10,000 条、128 维、1,000 次 Top10 查询，一半带等值过滤；有/无过滤 Recall@10 均须至少 0.95。写入占三分之一、查询占三分之二，每项计耗时60%、物理IO20%、容器峰值内存20%，建索引开销也计入。必须先功能全通过。下列方案按本题工程风险/潜在收益排序，不表示论文的性能排名。

float32 原始向量纯载荷仅 10,000×128×4 = 5,120,000 字节，约4.88 MiB；不包含记录、页、缓存、索引、分配器和容器其他内存。这是算术估计，不是实测峰值。先建立优化精确扫描，再决定是否值得付出ANN构建和内存开销。

## 1. 优化精确扫描：连续布局、SIMD距离计算、融合Top10选择（优先级最高，低风险）

论文依据：Yu等的SC15论文研究x86精确kNN内核，将距离计算和邻居选择融合以改善内存利用。其多点内核和平台上的加速不能直接当成本题单查询收益。

原文：[Performance Optimization for the K-Nearest Neighbors Kernel on x86 Architectures](https://doi.org/10.1145/2807591.2807601)；[作者机构PDF](https://padas.oden.utexas.edu/static/papers/sc15nn.pdf)。本次成功获取出版方摘要及机构PDF搜索摘录，机构PDF正文抓取超时，因此不声称已核对全文。

本题推断：保留逐维直接平方差的精确标量基线；将数据块顺序读取并直接更新小Top10，不物化所有距离、不排序全表。自写可移植标量与运行时CPU能力检查的SIMD路径。不能把多查询批处理吞吐外推到单客户端逐条SQL。

A/B：A=现有精确扫描；B1=只融合Top10选择；B2=加SIMD；B3=调整块布局。逐项隔离变量。记录距离内核耗时、SQL端到端耗时、分配次数、读字节、容器峰值。验算近乎相等距离、重复向量、非128维尾部、零向量及所有规定距离度量；浮点累加顺序与排序tie规则必须与题面一致，不能仅凭“数学精确”宣称实现Recall必为1。

## 2. 等值谓词前推，按匹配规模选择扫描路径（高收益机会，低至中风险）

论文依据：ACORN §1、§3区分前过滤精确扫描与ANN后过滤；后过滤在低通过率或谓词与相似性负相关时需要更大的候选集。SIEVE实验的PreFilter基线就是先谓词过滤、后SIMD暴力kNN。论文没有证明本题应上复杂过滤图索引。

原文：[ACORN](https://arxiv.org/html/2403.04871v1)；[SIEVE §6.1](https://www.vldb.org/pvldb/vol18/p4723-li.pdf)。

本题推断：先对行元数据判断过滤，再计算距离；若已有标量索引，可取匹配ID并按物理块整理，比较“候选ID访问”与“连续扫描+过滤”。匹配比例高时随机访问可能不合算。不应为每个标签复制完整向量或建完整图而未经内存/构建开销评估。

A/B：A=全量计算距离后过滤；B1=元数据过滤前推；B2=已有等值索引候选+分块访问。匹配率取0、0.1%、1%、10%、50%、100%，另含少于10条匹配；构造标签与向量独立、正相关、负相关三类。分别报告过滤与无过滤Recall@10；任何不到10条候选就扩大ANN结果的策略，仍不能由“够10条”推出召回合格。

## 3. 减少COW写放大：同一合法提交内只复制一次共享路径页（中风险，关系到写入和IO分）

论文依据：Rodeh的作者讲稿第6页提出一次checkpoint间已shadow页不必重复shadow、脏页批量顺序写；第9页指出普通B树叶页相邻链接与shadowing存在冲突。BPFS §2.3说明向根传播复制的成本及批处理摊销；其短路shadow paging依赖持久内存硬件原语，不能直接照搬到普通磁盘。

原文：[B-trees, Shadowing, and Clones，USENIX作者讲稿](https://www.usenix.org/legacy/event/lsf07/tech/rodeh.pdf)；[BPFS](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/BPFS.pdf)。

本题推断：在同一SQL语句/已授权事务内缓存新页、重用已复制的根到叶路径，提交时一次落盘；缓冲页设置上限。不要跨自动提交合并确认，也不要省略要求的同步。范围扫描采用路径栈或显式版本化链接，避免COW页的next指针把扫描导入旧树。

A/B：同一持久性协议和同一提交边界下，A=逐修改立即写新页；B=事务内页去重+顺序写。分别测单行自动提交和多行单事务、随机键和顺序键、分裂与删除。记录写入字节/逻辑数据字节、写系统调用、同步次数、峰值缓存页。故障注入必须覆盖新页写后/元数据发布前、发布中、确认后；恢复不能丢失已确认操作。若评测全部是单行自动提交，跨行批处理收益不成立。

## 4. 自研HNSW；过滤先保留精确路径，必要时试ACORN-1（中高风险，后置候选）

论文依据：HNSW算法1/2/5分别描述增量构图、层内候选搜索和查询；M影响边数和内存，efConstruction与ef控制不同阶段的质量/成本。ACORN §5.3将ACORN-1邻居扩展放在查询期，考虑一跳与两跳邻居再过滤，意在降低索引时间和空间成本。不能把它简化成“普通HNSW只访问匹配点”。

原文：[HNSW全文](https://arxiv.org/pdf/1603.09320)；[ACORN §5.3](https://arxiv.org/html/2403.04871v1)。

A/B：A=优化精确扫描；B=自研HNSW仅用于无过滤查询，过滤仍精确；C=过滤采用ACORN-1式扩展。初始小网格M∈{8,16}、efConstruction∈{64,128}、efSearch∈{32,64,128,256}只是实验取值，不是论文保证。将建图时间、写入维护、落盘IO、重启恢复、删除更新、访问标记及邻接表峰值全部计入。至少多个构图种子；用独立查询集验证两类Recall，而非在评测查询上调参。

ACORN摘要的2–1000倍比较涉及百万至2500万向量、主要0.9召回条件；不能当作10k、Top10、0.95召回、端到端SQL及建索引计费下的收益预测。HNSW对高维任意数据也不是无条件对数时间保证。

## 5. RaBitQ压缩扫描+精确重排（最高实现风险，先测是否存在带宽瓶颈）

论文依据：RaBitQ把D维向量编码为D位，并有额外系数和变换；§4使用误差界触发原始向量精确重排。误差界给概率性质，不能将其说成每个查询必达0.95。原文明确距离相近时重排对高召回重要；检索保证还受被探测IVF簇的覆盖限制。

原文：[RaBitQ §3–5与附录F.3](https://arxiv.org/html/2405.12497v1)。

本题推断：128维纯二值码约16字节/条只是编码载荷，不能声称总内存32倍下降。需保留原向量重排，新增变换、系数和索引会占内存；10k规模甚至可能增内存。可先研究全码扫描，避免同时引入IVF簇漏召回；若省略论文组件，只能称启发式原型，不继承理论保证。

A/B：A=SIMD精确扫描；B=完整RaBitQ距离估计+误差界重排，保留精确回退。报告编码/构建开销、每查询旋转开销、候选数、原向量读取字节、两类Recall。测试距离高度集中的数据和多个随机旋转种子。论文实验主要约100万至234万向量、Top100；不能外推本题Top10。若本题耗时主要在SQL、提交或IO，则不优先实现该项。

## 统一实验门槛

1. 功能全通过后才比较性能；每个B项都能独立关闭并回退精确基线。
2. 固定数据、提交边界、CPU线程数和容器资源；记录冷/热条件。遵照评测口径读取容器峰值和物理IO，不用逻辑扫描字节代替物理IO。
3. 原始向量精确扫描作为地面真值。过滤地面真值是在满足谓词的集合内取Top10；不足10条和空集按题面口径处理。
4. 每项多次重复并保留原始记录，分别展示构建/写入/查询、两类召回及完整评分公式结果。性能计分必须套题面实际归一化/截断公式，不将几个相对百分比简单相加。
5. 论文来源只支持算法原理与论文自身实验；本题收益须以实际实验验证；已执行的局部实验另见 validation.md，不能视为正式得分。
