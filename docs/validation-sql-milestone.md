## 覆盖的行为

- 表命名空间隔离、相同主键跨表共存、极端有符号键、跨表提交和回滚；扫描过程中 UPDATE/DELETE 读取固定旧根，避免重复或跳行。
- 显式行编码、跨页记录、嵌入 NUL、Unicode 字符数及码点序、float32、非法长度/截断/尾部垃圾/非有限向量。
- CREATE、列清单、多行 INSERT、投影、AND 比较、多个排序键、LIMIT 0、主键点查、常量 UPDATE、DELETE、别名及不支持语法拒绝。
- 精确及带过滤的 TopK、空结果、距离并列、平方距离极近但显示距离相同、修改/删除/回滚后向量可见性。
- 4096 字节排序预算强制多段与多轮归并、内存参考排序对照、输出回调失败后临时目录清理。
- 语句失败不影响事务中先前成功语句；RLIMIT_FSIZE 注入 UPDATE 中途真实写盘失败，恢复保存点后仍能提交先前插入。
- 正常关闭回滚、跨表 _exit 恢复、实际 CLI 收到确认后 SIGKILL，再重启核对提交状态。
- CLI 90 步独立 Python 状态模型，每步验证过滤 TopK，并在重启后核对已提交主键；保留原存储 2200 次随机修改模型。
- 明确拒绝旧磁盘格式 01，没有自动覆盖或迁移。

## 发现与修复

SQL/命名空间初始失败证据为缺失 API 引起的编译失败；CLI 初始断言指出数据库可执行文件不存在。没有将这些记录描述成尚未发生的运行时失败。

独立规格审查发现 VARCHAR(1) 列与 'aa' 比较被错误地套用存储宽度。新增回归实际报 text exceeds scalar length；修复为查询常量只做类型和完整 UTF-8 验证，INSERT/SET 仍检查列长度。修复后七组相关测试通过；独立审查重新验证 SELECT、UPDATE、DELETE、LIMIT 0 与写入限制。

独立规格审查最终通过：八组重点测试 8/8、8.71 秒；另用 120 行、16 组结果核对 Unicode 多列排序、过滤 L2 的堆和外排路径、流式修改及回滚。审查结论只针对当前里程碑。

独立代码质量审查也通过：八组重点测试 8/8、7.98 秒。额外真实写盘失败探针验证自动提交 UPDATE/DELETE 中途失败恢复所有旧行；显式 CREATE 在表元数据写出后失败，撤销该语句并保留此前插入，随后继续建表、提交和重启均正确。审查报告保存在 docs/reviews/；没有未解决的阻塞项。

此前核心修复仍保留：写失败后只有完整页写出才推进分配；按平方距离排名，避免 sqrt 舍入合并近距离；mkdtemp 避免容器 PID 复用污染用例。

## 性能证据和待测方向

旧局部基准 bench/results/exact-scan-squared-reference.json：10000 条 128 维、1000 次 Top10，半数带过滤，三轮结果均与平方距离全排序一致。全排序中位数 765.482 ms，有界堆 541.186 ms，局部时间比 1.41445。它不含 SQL、IO 或持久化，不能当成本轮 SQL 提速或比赛分数。

SQL 扫描已过滤后再计算距离，但仍整行解码。延迟物化、按需解码、有限批量执行和 COW 批内复用是后续独立 A/B 方向；本轮没有宣称这些尚未实现的收益。研究见 sql-execution-research.md。

## 剩余限制

- 未获得正式协议、错误码、模式切换、公开用例和冻结资源包；本地 dev-tsv 接口不是官方兼容性证明。
- 未实现 ANN、空间回收、页缓存或批内页复用；16 层不可变 radix 的写放大明显。
- 排序预算不是总 RSS 上限；单行、SQL 解析、IO 缓冲及分配有额外开销。进程强杀可能留下本查询的临时排序目录，尚未自动回收历史孤儿目录。
- 不提供断电/磁盘损坏保证；本题恢复模型是进程终止。首次目录同步失败后重开未重试目录同步的旧健壮性缺口仍未扩展处理。
- 基础镜像和直接依赖锁定，apk 传递依赖尚未完整离线归档。
- 学习材料标明用户、Agent、工具来源；Agent 实现、审查和解释不自动证明用户理解。
