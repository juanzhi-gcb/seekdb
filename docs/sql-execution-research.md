# MiniVectorDB：SQL 执行层文献与最小 A/B 建议

日期：2026-11-09。只读调研；没有改动仓库、生产数据或全局配置，没有执行性能实验。下列收益都是待验证假设，不是竞赛提分证据。已读取项目 AGENTS.md、docs/performance-research.md、src/vector/exact.cpp 和 include/minivectordb/store.hpp。

后续记录：本文保留 SQL 里程碑时的研究假设。按需解码与不可变批量写入已在下一阶段实现并对照测试，实际结果见 [优化报告](optimization-results.md)，不将后来的结果改写为当时已知。

## 本阶段唯一优先建议

先实现并验证“按需解码”：扫描记录时先解码 WHERE 需要的字段，拒绝的行不构造向量和投影对象；通过过滤后才解码距离需要的向量；最终 TopK 只存稳定键和距离。投影延迟到获胜行再读取可作为后续独立 B2，前提是整个查询使用同一工作根且无中途修改。

理由：现有 exact_top_k 已有 O(k) 堆、过滤先于距离计算，并仅对获胜项求平方根。不能把这些已存在的机制当作新优化。新的 SQL/行编解码接口应防止调用 VectorSource 之前已经解码整行，从而抵消前过滤收益。扫描返回的 string_view 只在回调期间有效，堆或批次不可保存悬空视图。

这里节省的首先是 CPU、临时对象和分配；若当前存储仍整条读取，不能宣称减少物理 IO。不要同时变更布局、SIMD、TopK 容器和批大小，否则无法归因。

## 1. 延迟物化与谓词前推

论文：Abadi、Myers、DeWitt、Madden，Materialization Strategies in a Column-Oriented DBMS，ICDE 2007。

原文：https://www.cs.umd.edu/~abadi/papers/abadiicde2007.pdf

核验：成功取得作者机构全文，重点核对引言和 §2–3。作者比较先组合元组再过滤，以及先筛选位置、交集后重建元组；同时明确重读列的代价，因此延迟物化不是所有查询都更快。论文对象是列存分析负载，不能把其 IO 结论直接移植到本项目行存。

本项目推断：借鉴“避免为将被丢弃的行构造对象”，无需实现列存、位置位图或代价优化器。WHERE 的类型检查、NULL/三值语义和报错规则需保持一致；仅对可安全提前求值的简单谓词做前推。

A/B：A=读取同样记录、整行解码、过滤、既有 exact_top_k；B1=同样扫描和距离内核、仅按需解码；B2=在 B1 上仅对最终获胜键重读投影。分别统计扫描行数、向量解码行数、距离计算次数、分配次数、投影重读次数、端到端耗时及峰值内存。B2 可能增加树查找/IO，应独立决定是否保留。

## 2. Volcano 与有限批量执行

论文：Boncz、Zukowski、Nes，MonetDB/X100: Hyper-Pipelining Query Execution，CIDR 2005。

会议全文：https://www.cidrdb.org/cidr2005/papers/P19.pdf

核验：成功取得全文，重点核对摘要、§4 与 §5.1.1。论文把逐元组解释开销与整列中间结果的带宽压力分开，采用有限大小的批量向量算子；批大小需要结合所有中间向量的总宽度和缓存。论文默认 1024 不是本项目 128 维向量的最优参数保证。

本项目推断：当前融合回调已经比“每个表达式每行虚函数调用”简单，不能假设换 nextBatch 必然更快。先让表扫描直接完成过滤、距离、TopK；仅在剖析证实算子分派/解码占比大时，比较可复用的有上限批次。这里的 vectorized execution 指批量处理行，不等于 embedding SIMD。

A/B：A=融合逐行回调；B=相同算法和数据访问的 64/256/1024 行批次。预算按字节而非只按行数，包含向量、选择索引、变长字段和容器容量；128 维 float32 的 1024 行仅向量就占 512 KiB。测热/冷端到端时间、分配、批内峰值；不得把整张表收集成一个批次。

## 3. TopK 超出内存时的研究边界

论文：Chronis、Do、Graefe、Peters，External Merge Sort for Top-K Queries: Eager input filtering guided by histograms，2020。

作者机构页：https://research.google/pubs/external-merge-sort-for-top-k-queries-eager-input-filtering-guided-by-histograms/
出版入口：https://doi.org/10.1145/3318464.3389729

核验：取得 Google Research 的作者摘要；出版全文抓取返回 403，未核对算法细节、证明和完整实验。摘要提出用执行时直方图在排序或写临时存储前消除部分输入，面向所需输出本身超出内存的 TopK。其性能倍数不用于本项目预测。

本项目推断：默认 Top10 的排序状态很小，继续使用既有有界堆；不要为了论文新颖性添加直方图算法。ORDER BY LIMIT 的 K 必须基于实际排序键、记录标识和返回载荷估算内存；若支持 OFFSET，则候选数通常为 OFFSET+LIMIT，需检查溢出和预算。无 LIMIT 或候选状态超预算时切到有限内存外排。

A/B：小 K 比较全排序基线和既有堆，验证结果一致且只保留 O(k) 排序状态；大 K 仅比较正确的普通外排路径，暂不实现全文未核验的直方图算法。测试 K=0、1、10、N、N+1、空集合、重复距离/键、多列 ASC/DESC 与 NULL 顺序。未建立可证下界时不能扫描到十条便停止。

## 4. 可落地的外部归并排序

论文：Graefe，Query Evaluation Techniques for Large Databases，ACM Computing Surveys 1993；此处使用作者 1993-11-10 修订稿。它是作者综述而非新 TopK 算法论文。

全文：https://cs.uwaterloo.ca/~david/cs848s13/graefe.pdf

核验：成功取得全文，重点核对排序章节的内存运行段、归并和记录/键-RID 对选择。该章节比较固定内存内排序产生运行段与 replacement selection，并讨论变长记录下后者的内存管理成本。

本项目推断：首版选择更简单的固定字节预算运行段排序、写临时段、有限路数归并。归并的输入缓冲、输出缓冲、堆和变长排序键也纳入同一预算，不能为每段无限开一个缓冲。最终归并可流向结果接收器，避免再物化完整结果；如果外层 API 仍返回全量 vector，则整个查询仍没有有限内存保证。临时段只属于查询，不加入数据库提交根；错误/取消应清理本次临时文件。

A/B：预算设为足以强制产生多段的小值，比较内存参考排序的完整输出；再比较最终结果物化与流式输出的峰值、临时读写字节和耗时。专门覆盖变长超大单行、重复排序键、多个归并轮次、磁盘写失败和空输入。单条记录超过预算必须有明确受限处理或可解释错误，不能无限扩容。

## COW 批处理：沿用已有文献，暂不和 SQL 优化混测

已核对 Rodeh 作者讲稿第 6 页的 checkpoint 间避免重复 shadow 与批量顺序写：
https://www.usenix.org/legacy/event/lsf07/tech/rodeh.pdf

本项目额外约束：现有 Savepoint 保存工作根。即使页尚未提交，只要旧保存点能到达该页，也不能简单原地修改；批内复用需要区分保存点代际、保留旧版本或使用明确回滚机制。所有表及目录仍由一个提交根原子发布，不跨自动提交边界合并确认，不减少既有 durable sync。

后续独立 A/B 应固定同一事务语句序列和同步次数，对比逐路径复制与保存点安全的批内复用，记录实际写字节/逻辑字节、峰值脏页。先验证跨表回滚、语句失败恢复、保存点恢复、提交失败和崩溃恢复，再计性能。

## 验收与收益口径

先全部功能正确，再运行 10,000 行 ×128 维、1,000 次 Top10，其中半数等值过滤。另做匹配率 0、0.1%、1%、10%、50%、100% 和少于十条命中；过滤地面真值是在匹配集合内进行相同精确排序。SQL 返回值、顺序、NULL、异常行为与基线一致；固定距离累加和 tie 规则。

所有 A/B 固定数据、查询序列、线程、提交边界、持久化配置和资源限制；冷/热分开，多次运行保留原始记录。分别记录插入与查询时间、容器峰值、物理 IO 和应用层逻辑读写，不能用逻辑字节代替物理 IO。时间60%、IO20%、内存20%，查询权重2/3，只能套用题面真实评分公式，不能直接相加相对优化百分比。预计 SQL 按需解码最值得先测，但未实测前不承诺提速。
