# Validated data-page buffer

Each Store optionally owns a lazily allocated fixed array of four-way sets. Entries store one4096-byte immutable page, physical page ID and recency rank0..3; the budget includes padding and set metadata. Lookup chooses page_id % set_count and searches at most four ways. A hit makes the entry most recent using bounded ranks, avoiding an overflowing timestamp. On a miss, an empty entry or the least recent entry in that set is used only after full page validation succeeds. This is set-associative LRU within each set, not a global LRU or2Q implementation.

Only packed and overflow data pages are eligible. Existing index caching and scan-local packed caching remain separately selectable. Root records are read from disk at reopen; no dirty or partially written page is admitted. Admission requires a complete read, magic, checksum, expected type and structure validation. Physical-address range and expected type are checked on every cache lookup; packed references retain format/tag/slot checks on every extraction. Every SQL row is still validated for structure, UTF-8 and finite vectors even if its containing page hits.

Successful append addresses are never reused within the Store lifetime, including rollback and savepoint restoration. An unsuccessful partial page cannot be referenced by a published working root, and is not cacheable; retry can safely overwrite only that unreachable address. Cache identity is local to one exclusively locked Store and dies at close. External mutation of a live database file remains unsupported; close/reopen revalidates changed disk content.

Reads retain owned Page/row copies so callbacks can recursively scan or mutate without dangling cache references. The cache cannot change key order, exact result ties, file bytes, commit boundaries, two synchronization calls per commit or format02/03 compatibility.

Data-cache statistics are independent of index-cache statistics. capacity_bytes reports the actually allocated array (zero before lazy allocation); resident_pages counts occupied entries. reset_data_cache_stats resets hits/misses/evictions only. A budget smaller than one complete set disables allocation. The low-level Store default remains0. SQL defaults to16MiB and disables the scan-local memo, selected after the experiments in buffer-results.md. The tested array uses16,776,960 bytes for4,080 page slots. Restore prior SQL behavior with both data_cache_bytes=0 and packed_scan_cache_bytes=1048576. Current row strings, index and scan caches, allocator/fixed object overhead, SQL work state and benchmark truth data are additional memory, not included in this budget.
