# 持久化平坦向量索引

CREATE VECTOR INDEX name ON table(vector_column) 创建真实的独立磁盘命名空间，以主键映射 float32 向量。索引名在表内唯一，列必须为 VECTOR。建索引流式读取已有表，使用与 DML 相同的有界批次（128条/512KiB，超大单条单独处理）；不全量加载向量。

表目录的正键继续表示表，负键表示索引元数据，0 保存共享命名空间分配器。格式02/03数据文件无需迁移；打开已有无索引文件继续工作。索引页、表数据和目录在同一 Store 提交根下。建索引失败、DML失败和显式回滚恢复共同保存点；已确认提交使用现有两次同步，不依赖 shutdown 落盘。

单个升序 L2 ORDER BY、带 LIMIT 且 K 落入堆预算时，通过索引枚举向量；主键直接查找和通用排序仍用正确的表扫描路径。索引候选逐行核验原始记录并应用 WHERE，确保过滤后 TopK、距离和主键并列规则不变。ExecutionInfo.vector_index_entries_examined 可用于测试确认执行了索引路径。

后续本地优化使用 Store.scan_equal_in 同步遍历索引与表的相同主键前缀，避免对每条记录重新走16层根查找。默认 Options.paired_index_scan=true；设为false可运行原参考路径。完整行校验、索引向量核验、过滤和最终结果回查保留。新路径还会拒绝两侧主键集合不一致，包括旧路径不能发现的缺失索引项。

同步扫描先固定一个提交根并定位两侧命名空间，然后开始回调；使用一个有界扫描缓存、每层两份页副本和当前两条记录，不保存整表。回调期间允许修改和回滚，已经捕获的不可变页与记录视图仍有效；如较晚发现集合不同，之前的回调不会撤回。SQL的JSONL结果暂存保证此类错误不输出半条成功响应。详见 [同步扫描实验](paired-scan-results.md)。

exact 和 ann 模式都使用穷举精确检索，理论目标 Recall=1，实际以查询对照测试为准。不实现近似剪枝，也不将算法名称冒充性能收益。重复向量存储及逐行回查增加写入和扫描成本，后续需单独性能实验，不能沿用上一版缓存基准推算本轮得分。

旧程序没有索引维护逻辑，因此有索引的数据不应交给旧二进制写入。此处兼容性指新程序读取既有02/03表，而非旧程序理解新增目录记录。仍无空间回收；进程强杀后未提交追加页不可见但会占文件空间。
