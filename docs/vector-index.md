# 持久化平坦向量索引

CREATE VECTOR INDEX name ON table(vector_column) 创建真实的独立磁盘命名空间，以主键映射 float32 向量。索引名在表内唯一，列必须为 VECTOR。建索引流式读取已有表，使用与 DML 相同的有界批次（128条/512KiB，超大单条单独处理）；不全量加载向量。

表目录的正键继续表示表，负键表示索引元数据，0 保存共享命名空间分配器。格式02/03数据文件无需迁移；打开已有无索引文件继续工作。索引页、表数据和目录在同一 Store 提交根下。建索引失败、DML失败和显式回滚恢复共同保存点；已确认提交不依赖 shutdown 落盘。

SQL 默认使用 `CommitSyncPolicy::ProcessCrash`：完成新页写入后写提交根，对整个文件执行一次 `fsync` 才确认成功。其恢复承诺限于进程被强制终止、内核与文件系统仍存活；未确认提交遇到断电、内核或设备故障不属于同一模型。`Ordered` 保留写根前的数据同步与写根后的同步两道屏障，底层 Store 默认仍使用 Ordered。两种策略都保持表、索引和目录的共同提交边界，提交 I/O 失败后均须关闭并重新打开数据库。

单个升序 L2 ORDER BY、带 LIMIT 且 K 落入堆预算时，可通过索引枚举向量；主键直接查找和通用排序仍用原路径。冷索引扫描逐行核验原始记录并应用 WHERE，确保过滤后 TopK、距离和主键并列规则不变。`ExecutionInfo.vector_index_entries_examined` 记录实际索引遍历；命中下面的查询缓存时可以为 0，不能用它单独判断是否拥有持久化索引。

冷索引路径使用 Store.scan_equal_in 同步遍历索引与表的相同主键前缀，避免对每条记录重新走16层根查找。默认 `Options.paired_index_scan=true`；设为 false 可运行原参考路径，并关闭索引上的数值列缓存路径。完整行校验与索引向量核验在冷扫描/完整构建时执行，过滤和最终结果回查保留。同步扫描还会拒绝两侧主键集合不一致，包括旧路径不能发现的缺失索引项。

同步扫描先固定一个提交根并定位两侧命名空间，然后开始回调；使用一个有界扫描缓存、每层两份页副本和当前两条记录，不保存整表。回调期间允许修改和回滚，已经捕获的不可变页与记录视图仍有效；如较晚发现集合不同，之前的回调不会撤回。SQL的JSONL结果暂存保证此类错误不输出半条成功响应。详见 [同步扫描实验](paired-scan-results.md)。

exact 和 ann 模式都使用穷举精确检索，理论目标 Recall=1，实际以查询对照测试为准。不实现近似剪枝，也不将算法名称冒充性能收益。重复向量存储增加写入和冷扫描成本；后续优化须单独测量，不能沿用旧缓存基准推算正式得分。

SQL 查询缓存共用 `Options.scan_snapshot_bytes` 的默认及硬上限 8 MiB，0 关闭。默认 `typed_scan_cache=true`：合适 TopK 无 WHERE 或 WHERE 只涉及 BIGINT 时，将完整验证后的向量及所有 BIGINT 列复制到自有对齐数组。缓存绑定表、索引和向量列身份；无索引时身份中的索引 ID 为 0。首次合适查询仅观察，第二次扫描尝试构建，所有原始行和冷索引一致性检查通过后才发布，包括不满足构建查询过滤条件的行。

数值缓存命中时直接比较 BIGINT、读取向量 span，每次重新执行过滤与精确 TopK；不重新解析无关 VARCHAR、不重复完整行验证或复制候选向量。获胜行仍回查原表并完整校验后投影。`typed_rows_examined` 与 `typed_cache_bytes` 分别记录数值缓存访问和已分配预算；它们不冒充执行过的原始行校验次数。

不适用数值缓存的路径（例如 VARCHAR 谓词）保留原始行快照/流式扫描。原始行快照命中仍完整校验每行，其访问记在 `snapshot_rows_examined`。两种缓存互斥：切换前先释放上一种有效负载，不会同时分配两个 8 MiB 缓冲区。普通查询、主键等值直接查找及一般排序沿用原路径。`typed_scan_cache=false` 可单独恢复旧原始行路径作为对照。

任意已解析的非 SELECT 语句在绑定/执行前失效两种缓存，包括 BEGIN、COMMIT、ROLLBACK 及失败的 DML/DDL；语法解析失败没有状态变更，保留有效缓存。失效清除已用行数与身份；`reuse_scan_snapshot_buffer=true` 允许保留相同布局的分配，不能读取旧内容。构建失败、超容量或缓存类型切换会释放负载，不发布部分结果。

原始行预算包含连续缓冲区及每行 16 字节头；数值预算包含 float 数组、BIGINT 数组和列映射。固定对象、分配器、当前行及查询临时空间另计。超过预算立即释放并保持磁盘流式扫描，同一身份不重复尝试直到状态失效；因此不要求全表驻留。缓存不持久化，重启后为空，磁盘格式未变。外部修改已打开文件与现有页缓存一样不受支持；关闭重开会重新验证磁盘内容。

`validated_vector_kernel=true` 使 SQL 使用私有的候选已验证距离入口：原始行/索引候选已有解码校验，数值缓存候选已有完整构建的验证证明。查询向量每次仍检查有限性，每个候选仍检查维度，只省去重复的逐分量有限性检查。double 累加顺序、sqrt 后比较和有符号主键并列规则不变；公开 `exact_top_k` 和 `l2_distance` 保留完整输入检查。false 选择检查版对照，不允许将私有入口用于尚未验证的外部向量。

原始快照历史实验见 [快照优化报告](scan-snapshot-results.md)，本轮数值缓存、资源与提交策略的测量和验证状态见 [得分优化记录](score-first-results.md)。这些本地结果不等于正式 E 或排名。

旧程序没有索引维护逻辑，因此有索引的数据不应交给旧二进制写入。此处兼容性指新程序读取既有02/03表，而非旧程序理解新增目录记录。仍无空间回收；进程强杀后未提交追加页不可见但会占文件空间。
