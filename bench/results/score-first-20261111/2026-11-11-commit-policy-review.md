## 结论与适用边界

**可批准独立原型和双策略回归，不能仅凭本报告直接宣布生产安全或提升幅度。** 在题面限定的故障模型下，`全部 COW 页完整 pwrite → 新根记录完整 pwrite → 同一 fd 的 fsync 成功 → ACK` 可以成立；它减少的是根发布前的独立落盘屏障，最终 fsync 和成功响应之间的顺序保持不变。

证明前提为：单写者、同一普通文件/同一存活内核与挂载、正常且提供写后读一致性的本地文件系统、无并发外部改写、无真实媒体/写回错误、仅杀死数据库进程，不重启宿主或丢弃内核状态。不能把进程崩溃推导扩展成断电、内核崩溃、NFS 服务端故障或磁盘损坏保证。这里的所有“不确定提交可全旧/全新”结论均受这些前提约束。

## Linux 接口事实与本次推导

- pwrite 可以短写，调用方必须完成剩余部分；其指定偏移不会移动普通文件偏移。[Linux man-pages: pread/pwrite](https://man7.org/linux/man-pages/man2/pwrite.2.html)
- 在提供 POSIX 一致性的文件系统上，完成写入后发生的读取应看到新数据；写成功本身不等于已落盘。[Linux man-pages: write](https://man7.org/linux/man-pages/man2/write.2.html)
- fsync 成功才确认文件数据及必要元数据同步完成；新建文件的目录持久化需独立考虑。EIO/ENOSPC 等必须传播。[Linux man-pages: fsync](https://man7.org/linux/man-pages/man2/fsync.2.html)
- Linux 文件页缓存属于 inode/address_space，独立于用户进程对象；真实写回错误与调用方注入的返回码不是同一故障。内核文档还指出，某次 fsync 报告写回错误后，后续 fsync 可能返回 0，不能凭一次重试成功推断丢失页已补写。[Linux VFS: address space and writeback errors](https://docs.kernel.org/filesystems/vfs.html#the-address-space-object)

据此推导：只杀进程不会回滚此前完成的文件写入，也不会像断电一样抹掉全部脏页。新根开始写入时，其可达的新页已经完整进入文件的内核状态；旧根依赖的页没有原位修改。最终 fsync 返回成功后，新根及其依赖才共同具备可确认的持久性。该推导依赖上述故障模型，不是 Linux 对任意故障的事务保证。

## 崩溃与错误逐状态审查

设 S 是上次确认状态，N 是本次事务完整状态。假设没有 CRC 碰撞或任意外部篡改；CRC 是现有实现的撕裂检测手段，不是硬件原子页写承诺。

| 终止/错误边界 | 可见根与重启结论 | 必须保持的程序行为 |
| --- | --- | --- |
| BEGIN 后、尚未发出提交请求，任意 COW 页写入中/后 SIGKILL | 磁盘根仍指向 S；新增页不可达，恢复 S | 绝不能在修改语句内部提前发布事务根 |
| COW 页短写、EINTR | 正数短写补齐；EINTR 重试；未完整页不能得到已发布地址 | 写入循环与语句保存点不变 |
| 数据 pwrite 返回 0/注入 EIO/ENOSPC，尚未 commit | 工作根赋值尚未完成；语句恢复旧工作根，较早成功语句仍可提交 | 不能因新策略忽略写错误；真实媒体故障不在这项“可继续”的证明内 |
| 提交请求已进入，根写入前 SIGKILL | 根仍为 S，恢复 S | 此结果符合不确定提交约定 |
| 根 pwrite 部分完成后 SIGKILL/错误 | 根可能仍旧、CRC 无效，或有效新根；前两者选 S，后者恢复完整 N，因为 N 的页已先完整写入内核文件状态 | 不依赖单次 4KiB pwrite 原子性；不回滚可能已发布的新根 |
| 根完整写完、最终 fsync 尚未调用/未结束时 SIGKILL | 同一内核重新打开可恢复完整 N；允许未收到成功的事务已经生效 | 这不表示 N 在断电下也已安全 |
| 最终 fsync 被 EINTR 打断，进程仍活着 | 继续等待同步，不发送成功 | 保留 sync_fd 的 EINTR 重试 |
| 最终 fsync 成功、ACK 尚未完整发送时 SIGKILL | N 已持久化，恢复 N；客户端仍可能认为结果不确定 | 协议层不能把输出失败改说成“已回滚” |
| ACK 已完整发送之后 SIGKILL | 恢复 N，已确认结果保留 | 必须保证 ACK 在 fsync 成功之后；包含自动提交 |
| 最终 fsync 返回真实 EIO/ENOSPC | 没有可确认的持久化结果；不能保证任意介质故障下必定可恢复 S/N | 不 ACK 成功；poison/关闭并报告不确定或 I/O 错误，不继续服务、不伪造回滚成功 |
| 恢复过程中反复 SIGKILL | 恢复目前只读，不发布新根，重复重开应得到相同完整可见状态 | 原型需实测；不要为新策略加入未经验证的恢复写入 |

根只在前 36 字节保存有效字段，其余为零。因此“根短写后抛错”并不保证一定恢复 S：例如已写满 36 字节后，旧槽剩余零字节与新根一致，整个新根可能已经有效。测试应允许不确定事务恢复 N，不能把这种结果误判为回滚漏洞。

## 现有恢复检查是否足够

对上述无真实 I/O 故障的纯进程崩溃证明，足够使用现有不变量；不需要为了省一个屏障新增全库恢复扫描。但现有检查并不证明整棵树的任意损坏恢复：

- valid_root（88 行附近）只查根魔数/CRC、extent 在文件完整页数内、root 在 extent 内。
- open 选较大 generation 后，临时用发布 extent 验证根 branch 页；没有递归验证全部可达子页。随后 next_page 改成当前文件长度，供追加新页使用。
- 如果被选中的新根分支或更深子页坏了，目前直接报损坏，没有遍历旧根再自动回退的流程。文件长度足够也不代表中间所有页都已成功写回。

**明确反例：** 两阶段屏障合并后，根槽及文件长度可以先到持久设备，某个新子页仍只在内存；在最终 fsync 成功前断电，重启可能看到 CRC 正确且 extent 合法的新根，却在根页或更深子页读取时报错。完整 N 不成立，当前恢复也不保证退回 S。ext4 默认元数据日志本身不能充当数据库内容事务。[Linux ext4 journal 文档](https://docs.kernel.org/filesystems/ext4/journal.html)

这不是纯 SIGKILL 的反例，因为 SIGKILL 保留存活内核中的文件状态；但它禁止把新模式描述为“与原模式完全同等断电安全”。原有双屏障更早确认依赖页持久化，正是为根发布构造该顺序。

同样，真实 fsync 错误可能代表某些页没有落盘甚至不能再由缓存完整读出；新根 CRC 和 extent 无法修复这些页。不能依据用户态 wrapper 注入 EIO 后 reopen 通过，宣称真实 EIO 后总能全旧/全新。CRC 也不是无碰撞的事务提交标记。针对媒体错误的严格恢复需要单独设计，且 WAL 同样不能自动弥补所有介质损坏。

另：首次创建如果在写入首个有效根之前被杀，现有初始化可能留下没有有效根的文件；本报告没有将其修复或纳入“已经建立数据库”的提交证明。若正式门槛覆盖首次启动未 ready 的终止，应独立验收此边界。

## 推荐的独立实验与验收

采用显式双策略：`ordered` 保留原两道 fsync，`process_crash` 使用根后单次最终 fsync。原型必须在独立测试/构建路径运行，不与本轮查询缓存改动混为一个因素。两策略不改变格式 02/03，且不得通过模糊注释隐藏故障模型变化。默认切换由主 Agent 在实验通过后单独决定。

1. **事件顺序验收：** linker wrappers 记录同 fd 上的数据页完整写、根完整写、fsync 返回、ACK。process_crash 必须每次真实提交一轮最终同步；ordered 为两轮；初始化和目录同步另计。测试不能只数函数调用而忽略失败/短写后的补写。
2. **确定性 SIGKILL：** 外部父进程在每次数据 pwrite 前后、根 pwrite 前后、最终 fsync 前/进入后/成功后、ACK 前后设握手停点，再杀子进程。每个子进程在自己的 D 盘目录运行；不杀宿主、不改 swap、不全局 drop_caches。重开检查全表/目录/索引/查询完全为 S 或 N，已 ACK 只能 N，未请求提交只能 S。
3. **根短写矩阵：** 覆盖字段边界 1/7/8/9/15/16/17/23/24/25/31/32/33/34/35/36/37/137/512/4095 字节，补写成功、下一次 EINTR、下一次 EIO/0、立即被杀四类。补充多代轮换及 generation 字节进位边界（255→256 等），两个根槽均覆盖；有条件做 1..4095 全截断点小文件回归。承认 CRC 的概率性检测边界。
4. **数据短写和语句原子性：** 保留全部既有存储错误回归；覆盖每个 COW 层、溢出值、多页批次、表目录与多个向量索引、显式事务较早成功语句、失败语句后继续/回滚/提交。
5. **同步错误分类：** fsync 注入 EIO 是控制流测试，要求不 ACK 成功、Store/Database poisoned、不能继续 SQL。不能以该测试证明真实介质故障恢复。现有 tests/adversarial_storage_tests.cpp:32 直接返回 EIO 而不调用真实 fsync，必须在报告中标明。适配按策略实际同步点，不能保留对单同步模式不存在的第二次同步注入。
6. **跨路径完整性：** 自动提交、显式提交、空事务、DDL、事务失败保存点、EOF/shutdown 回滚、恢复期间再次 kill、开关缓存、格式02/03、较大文件与低内存；同一文件先后用两模式重开，确认没有模式专属的隐藏磁盘布局。
7. **端到端证据：** 原有正式公开/协议测试全过后，再独立记录100条每批的端到端写入、物理I/O、容器峰值，3轮以上交替顺序；最后才与查询缓存组合测试。当前约64%的诊断写入时间在200次fsync中，但两个同步点代价并不相同，不能从同步次数减半直接预测1.5×或2×写入速度，更不能预测E排名。
8. **禁止减弱的项：** 最终同步、目录创建同步、成功响应顺序、失败语句保存点、COW地址发布规则、poison状态、CRC/范围检查均保留。禁止将“进程崩溃模式”做成不落盘/批次异步 ACK 的模式。

## 与完整 WAL 的取舍

在当前明确的纯进程崩溃评测中，单次最终同步策略侵入小、格式不变、可独立验证，值得先实验。它仅减少同步轮次，不能降低16层COW路径和旧页保留带来的写放大。

若目标扩大到断电期间不确定提交仍可靠全旧/全新，或长期写入/更新下的空间和写放大，完整 WAL/检查点更合适：事务记录与提交标记必须可校验、先持久化日志再确认，恢复需检测不完整尾部并保证重放幂等；检查点、日志截断/轮换、目录同步及恢复再崩溃均要证明。其实现和验证范围显著大于这次策略实验，不宜为了“只有一次 fsync”仓促同时改造存储格式。

最终建议：先保持已通过正式准入的旧提交可回退，在独立原型证明 process_crash 的精确边界并实测收益；通过后才考虑作为比赛模式，保留 ordered 作为更强排序策略。不要将真实 EIO、文件损坏或断电的保证混入纯 SIGKILL 验收结论。
